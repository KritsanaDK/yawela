# ยาเวลา

แอปเตือนกินยาแบบ offline-first สำหรับ Android และ iOS พัฒนาด้วย Flutter

## ฟังก์ชันที่มีแล้ว

- เพิ่ม แก้ไข พัก และเก็บรายการยาโดยไม่ลบประวัติ
- ตั้งหลายเวลาและเลือกวันในสัปดาห์
- กำหนดวันเริ่มและวันสิ้นสุดของคอร์สยา
- แจ้งเตือนในเครื่องตาม timezone พร้อม fallback เมื่อ Android ไม่อนุญาต exact alarm
- บันทึก `ทานแล้ว`, `ข้าม`, `พลาด` และแก้สถานะย้อนหลัง
- สถิติความสม่ำเสมอ 7 และ 30 วัน
- SQLite เป็นแหล่งข้อมูลหลัก ไม่มีบัญชีและไม่ส่งข้อมูลยาขึ้น cloud
- ฟรี 3 รายการยา ตรวจข้อจำกัดใน SQLite transaction
- ปลดล็อกไม่จำกัดแบบ non-consumable ซื้อครั้งเดียว
- จำสิทธิ์พรีเมียมไว้ในเครื่องเพื่อใช้งานต่อแบบออฟไลน์

## ตั้งค่าสินค้าพรีเมียม

รหัสเริ่มต้นในโค้ดคือ:

```text
medireminder.premium.lifetime.v1
```

สร้างสินค้าชนิด **Non-consumable / One-time product** ด้วยรหัสเดียวกันใน App Store Connect และ Google Play Console หรือส่งรหัสอื่นตอน build:

```bash
flutter build appbundle \
  --dart-define=PREMIUM_PRODUCT_ID=com.yourcompany.yawela.premium.lifetime.v1
```

ราคาบนหน้าจออ่านจาก Store โดยตรง แอปไม่มีราคาหรือสกุลเงินแบบ hardcode

สิ่งที่ต้องทำก่อนทดสอบการซื้อ:

1. ตรวจว่า Android `applicationId` และ iOS Bundle Identifier ใช้รหัสถาวร `com.ksn.yawela`
2. ตั้ง release signing ของ Android (โปรเจกต์ปัจจุบันยังใช้ debug key)
3. เปิด In-App Purchase capability ของ iOS
4. สร้าง/เปิดขายสินค้าและกำหนดประเทศกับราคาในทั้งสอง Store
5. ทดสอบผ่าน Google Play internal testing และ Apple Sandbox/TestFlight
6. มีปุ่ม “กู้คืนการซื้อเดิม” อยู่ในหน้าพรีเมียมและตั้งค่าแล้ว

> การซื้อและกู้คืนสิทธิ์ต้องใช้อินเทอร์เน็ตของ Store แต่ข้อมูลยา ประวัติ สถิติ และการแจ้งเตือนใช้งานออฟไลน์ได้

## หมายเหตุด้านความปลอดภัยของการซื้อ

เวอร์ชันนี้ใช้สถานะสำเร็จจาก Store และ cache entitlement ลง SQLite เหมาะสำหรับ MVP และการทดสอบขาย แต่สิทธิ์ที่ตรวจเฉพาะฝั่งเครื่องสามารถถูกแก้ไขได้บนเครื่อง root/jailbreak และตรวจ refund แบบทันทีไม่ได้

ก่อนขยายยอดขาย แนะนำเพิ่ม backend ขนาดเล็กเพื่อตรวจ purchase token/JWS กับ Google และ Apple แล้วคืน signed entitlement ให้แอปเก็บไว้ใช้ออฟไลน์ การเปลี่ยนส่วนตรวจสอบถูกแยกไว้ใน `PurchaseService._verifyPurchaseForMvp()`

## ข้อจำกัดของระบบแจ้งเตือน

- iOS เก็บ pending local notifications ได้จำกัด แอปจึงจัดคิว 60 เวลาที่ใกล้ที่สุดและเติมคิวใหม่เมื่อเปิดแอป บันทึกการทาน แก้ไขยา หรือกลับเข้าแอป
- ตารางประจำใช้ daily/weekly repeating notification เพื่อลดจำนวนรายการ
- รายการที่มีวันสิ้นสุดหรือวันเริ่มในอนาคตใช้ one-shot notification เพื่อไม่ให้เตือนก่อนเริ่มหรือหลังสิ้นสุด หากมีหลายเวลาควรเปิดแอปเป็นระยะเพื่อเติมคิวถัดไป
- Android ขอ `SCHEDULE_EXACT_ALARM`; หากผู้ใช้ไม่อนุญาต แอปจะใช้ inexact alarm แทนและแจ้งสถานะในหน้าตั้งค่า
- หลัง force stop, การปิดสิทธิ์แจ้งเตือน หรือข้อจำกัดแบตเตอรี่ของผู้ผลิต ระบบปฏิบัติการอาจหยุดการแจ้งเตือนจนผู้ใช้เปิดแอปอีกครั้ง
